Video ingest

dashcam footage sampled by ground distance, deduplicated into the ledger
run a video through the pipeline

The server reads the file from its own filesystem. Pushing a multi-hundred-megabyte dashcam file through a JSON body is the wrong shape for the problem — in a fleet deployment the bus uploads to object storage and this endpoint is handed the key.

how frames are chosen

By distance, not by frame. At 40 km/h a bus covers 11 m every second. Sampling every frame spends 95% of the compute on near-identical views; sampling every N frames either misses defects in slow traffic or floods the ledger at speed. With a GPS track, frames are chosen to be roughly the set distance apart on the ground.

Then hashed. Consecutive frames of the same defect look alike, so each candidate is perceptually hashed against the last twelve accepted frames and skipped if it is a near-duplicate — before the expensive inference runs.
